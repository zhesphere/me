# TASK-007｜移动端 Hero 视觉二次校准

- 执行模型：`GPT-5.6 Terra / Medium`
- 状态：READY FOR RELEASE

## 背景与目标

`TASK-006` 的源码、自动化与部署均通过，但真实手机 Safari 视觉验收未通过。问题不是缓存或规则未生效，而是把 CSS 几何盒子的剩余空间误当成了实际视觉空间。

本任务只在 430px 及以下，把中央球、附近行星和主要轨道作为一个整体视觉向上纳入首屏。标题、正文与 CTA 保持当前节奏；外围轨道可以自然延伸，但核心视觉必须在 Safari 底部工具栏上方完成。

## 视觉根因

- `.orbit-visual` 是正方形盒子，但主要轨道是位于盒子中心的扁椭圆；盒子顶部开始后，强视觉轨道仍要稍后才出现。
- `82vw` 缩放同时减小了核心冲击力，却没有改变组件视觉中心相对于 Safari 可用画布的位置。
- Safari 截图包含顶部安全区和悬浮底栏；Playwright 内容视口中的 `core.bottom` 余量不能代表肉眼可用的舒适空间。
- 因此 `TASK-006` 的数字验收成立，但视觉验收标准不成立。

## 允许修改范围

- `src/styles/global.css` 既有 `max-width: 430px` 中的 Hero / orbit 响应式规则。
- `tests/e2e/home.spec.ts` 中 TASK-006 的手机几何断言，改为组件响应式规则与不遮挡回归守卫。
- `artifacts/task-007/` 下的 360、390、430 手机比例验收截图。
- 本任务文件与 `PROJECT_HUB.md`。

## 明确不做

- 不修改导航、标题、正文、CTA、GitHub、轨道造型、行星、动画或星空。
- 不修改 768px、1440px、1920px 的任何共享规则。
- 不修改 Latest Signals、Creative Coordinates、Point of Origin 或其他页面区域。
- 不继续压缩文字区，也不继续显著缩小宇宙系统。
- 不以 Playwright 的单一 bottom 数字代替视觉验收。

## 实现原则

- 保持当前 `82vw / 360px` 视觉尺寸。
- 使用一个明确的手机端“轨道整体上提”响应式变量，位移由组件/视口宽度比例与 `clamp()` 共同决定，不针对具体 iPhone 写死。
- 位移只改变宇宙组件与后续 Hero 的构图关系，不覆盖 CTA，不改动画使用的 `transform`。

## 验收矩阵

- 360×800、390×844、430×932：分别产出完整 Hero 截图，以整体视觉重心、核心下方轨道空间和 CTA 呼吸感做人工视觉验收。
- 360px 无横向滚动；文字、Blog、GitHub 不被视觉遮挡；触控目标仍不小于 44px。
- 768×1024、1440×900、1920×1080 保持 TASK-006 的原始几何基线。
- `prefers-reduced-motion`、动画名称和粒子预算保持原状。
- 类型检查、单元测试、生产构建、完整 E2E 分别通过。

## 出口条件

- 用户明确确认真实视觉方向通过后，才提交、推送、部署并归档本任务。

- 为避免轨道贴住 GitHub，Hero 视觉入口间距调整为 `clamp(28px, 8vw, 34px)`；文字区自身的位置、尺寸和内部间距未改。
- 相对 TASK-006，宇宙整体最终净上移约：360px 为 34px、390px 为 35.5px、430px 为 39.1px；轨道尺寸仍为 `82vw / 360px`，没有继续缩小。
